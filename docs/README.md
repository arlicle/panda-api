## 能力状态标记

| 标记 | 含义 |
| --- | --- |
| **已实现** | 当前代码存在完整执行路径，可以作为 0.7.4 行为使用。 |
| **部分实现** | 存在数据结构或部分路径，但配置、边界条件或配套行为不完整。 |
| **仅设计** | 旧文档提出过，但当前代码没有对应实现。 |
| **已知缺陷** | 存在实现，但行为错误、不安全、不可构建或与文档明显不一致。 |

这些标记描述的是 `7deff42` 的事实，不代表未来版本承诺。

## 事实来源与优先级

遇到冲突时按以下顺序判断：

1. 当前 Rust 代码和内置前端 source map 中的实际执行路径；
2. 当前仓库的 JSON5 示例和 `README.md`；
3. `../arlicle.github.io/posts/2020/` 中的历史文章；
4. 文章中的未来设想、Todo 和界面描述。

语法参考中的每项重要能力均通过代码与示例或历史文章交叉核对。若实现和文章不一致，文档会明确写出差异。

## 文档边界

- 本套文档描述现状并给出兼容式升级方案，不重新定义 Panda API DSL。
- 未修改任何 HTTP 接口、Rust 类型、CLI 参数或 JSON5 行为。
- `_theme/` 只有编译产物和 source map，因此可以分析前端结构，但不能把它视为可维护的前端源码工程。
- 安全问题按服务可能绑定到非本机地址的情况评估；默认 `127.0.0.1` 只能降低暴露面，不能替代输入校验。

## 维护约定

- 修改 DSL、默认值或匹配规则时，同步更新[语法参考](03-syntax-reference.md)。
- 修改模块边界、运行时状态或路由时，同步更新[系统架构](02-architecture.md)。
- 完成路线图项目后，保留原问题记录并补充完成版本，避免失去迁移上下文。
- 发布二进制前，应先恢复可复现构建并记录工具链、`Cargo.lock` 和验证结果。
